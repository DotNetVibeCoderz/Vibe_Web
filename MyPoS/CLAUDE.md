# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MyPoS — a single-project **Blazor Server** point-of-sale app (`MyPoS.csproj`, `net10.0`) using **MudBlazor 9** and **EF Core**. Not a git repository; there are no automated tests.

The UI is **Indonesian** and defaults to Rupiah. Write user-facing strings, comments, and docs in Indonesian; code identifiers stay English.

## Commands

```powershell
dotnet build
dotnet run                          # https profile: https://localhost:7198 + http://localhost:5296
dotnet run --launch-profile http    # http only: http://localhost:5296
```

Seeded logins: `admin/admin123` (Admin), `manager/manager123` (Manager), `operator/operator123` (Operator).

Screenshots for the docs are regenerated by driving a headless Chrome over CDP — no npm install needed:

```bash
node docs/tools/screenshot.mjs http://localhost:5296 docs/screenshots
```

## Money, tax, and settings — the three rules that matter most

1. **Never hard-code a business value.** Tax rate, currency symbol/decimals, low-stock threshold, invoice prefix, loyalty ratio, session length, accent colour, payment credentials — all live in `Services/PosSettings.cs` and are edited from `/pengaturan`. Adding a setting = adding one property; it is persisted as a `Settings` key/value row via reflection, so **no schema change is needed**.

2. **Never format money with `ToString("C0")`.** Use the injected `MoneyFormatter` (`Format`, `FormatNumber`, `FormatCompact`). `"C0"` follows the server's OS locale and will render dollars on a non-Indonesian host.

3. **Never compute totals inline.** `Services/TaxCalculator.cs` is the single implementation of discount → service charge → DPP → tax → rounding, used by the POS preview, the Settings simulation, the REST API, and persistence alike. See `docs/pajak.md`.

`Transaction` snapshots `TaxRate`/`TaxInclusive`, and `TransactionDetail` snapshots `ProductName`/`UnitCost`. These are deliberate copies — without them, changing a tax rate or cost price would retroactively rewrite old receipts and reports.

## Checkout goes through one service

All transaction creation — the POS page *and* `POST /api/v1/transactions` — runs through `CheckoutService.CheckoutAsync`, which does stock validation, totals, the gateway call, stock deduction, and loyalty points inside one DB transaction. Do not re-implement any of that in a page or an endpoint.

Stock is deducted when the transaction is *created*, not when payment confirms, so the same item cannot be sold twice while a customer sits on a gateway page. `VoidAsync` and a failed `RefreshStatusAsync` restore it.

## Database: four providers, no migrations

`Data/DatabaseSetup.cs` picks the provider once at startup from `Database:Provider` — `Sqlite` (default), `SqlServer`, `PostgreSql`, or `MySql`. Things already handled, do not undo them:

- **`MaxLength` on every indexed string column** — MySQL cannot index unbounded text.
- **`decimal(18,4)` forced in `OnModelCreating`** — SQL Server silently uses `(18,2)` otherwise.
- **`Npgsql.EnableLegacyTimestampBehavior`** — transactions record local store time, which Npgsql rejects for `timestamp with time zone`.

`Data/DatabaseBootstrapper.cs` probes every table at startup. On a mismatch it **only recreates SQLite**, and only after copying the file to `mypos.db.bak-{timestamp}`. Server databases are never dropped — it logs an error instead. So editing `Models/Entities.cs` wipes local SQLite data (a backup is kept). See `docs/basis-data.md`.

## Data access pattern

`AppDbContext` is registered with `AddDbContextFactory`, never as a scoped `DbContext`. Every operation opens a short-lived context:

```razor
@inject IDbContextFactory<AppDbContext> DbFactory
...
using var db = await DbFactory.CreateDbContextAsync();
```

**EF translation trap:** projecting into a positional `record` constructor inside a `GroupBy` result does not translate. Project to an anonymous type, then map client-side. This has already bitten `Pages/Index.razor` and `Pages/Categories.razor`.

## REST API

`Api/` holds Minimal API endpoints grouped under `/api/v1`, documented by Swashbuckle at `/swagger`. Config lives under `Api:` (`Enabled`, `SwaggerEnabled`, `RoutePrefix`).

- **The `ApiKeyEndpointFilter` is attached to the group, not to individual endpoints** (`Api/ApiRoutes.cs`), so a new endpoint cannot be left unprotected. Keep it that way.
- Keys are PBKDF2-hashed with an indexed 12-char `Prefix` for lookup; read-only keys are rejected on POST/PUT/PATCH/DELETE. Managed from the Settings → API tab.
- Return DTOs from `Api/ApiModels.cs`, never entities — navigation properties would cycle.
- Swashbuckle 10 / Microsoft.OpenApi 2: types live in `Microsoft.OpenApi` (no `.Models`), and `AddSecurityRequirement` takes a `Func<OpenApiDocument, …>`.

## Storage

`IStorageService` has four providers chosen at startup from `Storage:Provider`: `FileSystem`, `AzureBlob`, `AwsS3`, `MinIO`. **AwsS3 and MinIO share `S3StorageService`** — same protocol, differing only in `ServiceUrl` and `ForcePathStyle`. Upload size comes from `MaxUploadMegabytes`, never a literal.

## Payments

`IPaymentGateway` (`Services/Payments/`) has four implementations: Cash, Xendit (Invoice API), Midtrans (Snap + Core API — different hosts), Stripe (Checkout Session, form-encoded). `PaymentGatewayResolver` exposes only providers that are both enabled *and* have credentials.

**Webhooks never trust their payload.** `/api/payments/{provider}/callback` reads only the invoice number, then re-queries the provider via `CheckStatusAsync`. Keep this property.

Stripe notes: IDR is *not* a zero-decimal currency there (amounts ×100), and the whole order is sent as one consolidated line item because Checkout totals must equal the sum of line items and negative lines are rejected.

## Master-data import

`Services/Import/` has one `IMasterDataImporter` per entity (Product, Category, Customer) plus
`Shared/ImportDialog.razor`, which is generic over all of them.

- **`ParseAsync` must never write.** It returns an `ImportPreview` of per-row actions and errors;
  `CommitAsync` writes only after the user confirms, inside one transaction that rolls back whole.
- Match keys: product = barcode else name; customer = phone else email; category = name.
- Duplicates *within the uploaded file* are errors too, and the message names the other row.
- `ExcelImportHelper` builds templates (Data + Petunjuk + hidden Referensi sheets) and reads cells.
  Numbers accept both `15000` and `15.000`; barcodes/phones are read as text so leading zeros survive.
- ClosedXML writes cross-sheet list validation as an x14 extension — Excel reads it, openpyxl cannot.
  Do not "fix" a dropdown that openpyxl reports as missing.

## PDF reports

`Services/PdfReportService.cs` (QuestPDF, Community License set in the static ctor) builds reports generically from `PdfColumn<T>`, `PdfSummary`, and filter labels supplied by the calling page — so the file always matches what was on screen.

**QuestPDF gotcha:** one child per container. Build the chain before calling `Text` (`if (col.AlignRight) cell = cell.AlignRight();` then `cell.Text(...)`); calling `Text` and then `AlignRight` on the same container throws `DocumentComposeException`.

## Auth

- `CustomAuthStateProvider` persists the session in `ProtectedLocalStorage`, so a page refresh no longer logs the cashier out. Because browser storage needs a live circuit, `_Host.cshtml` uses `render-mode="Server"` **without prerendering** — do not turn prerendering back on.
- Passwords and API keys are PBKDF2-SHA256 (100k iterations, per-user salt) via `Services/PasswordHasher.cs`. Legacy Base64 hashes still verify and are rewritten on successful login.
- Per-page roles: POS = Admin,Operator; Produk/Kategori/Pelanggan/Laporan = Admin,Manager; Transaksi = all three; Pengguna/Pengaturan = Admin. Authenticated-but-wrong-role users get an "Akses ditolak" panel from `App.razor`, not a redirect to login.

## UI conventions

- **`wwwroot/css/mypos.css` owns the design tokens; `Shared/AppTheme.cs` mirrors them into the MudBlazor palette.** Both must stay in sync — MudBlazor components read the theme provider, custom markup reads the CSS variables off the `body` class.
- **Theme toggling moves both halves.** `MainLayout.ToggleTheme` flips `_isDarkMode` *and* calls JS `setBodyClass`. Changing one alone leaves half the page on the old theme.
- **Every money value gets `class="num"`** (JetBrains Mono, tabular figures) and numeric table cells get `class="cell-num"` (right-aligned, no wrapping).
- Reusable pieces: `.panel`, `.stat`, `.struk` + `.leader` rows, `.tile`, `.badge`, `.empty`, `.toolbar`. `.glass-container` is a legacy alias kept only so stale markup does not break.
- Dialogs use `MudDialog` with `@bind-Visible`; confirmations use `JSRuntime.InvokeAsync<bool>("confirm", …)`; feedback uses `ISnackbar`.
- Charts: single-series, `--chart-1` token (validated for lightness/chroma/contrast in both themes), direct-label the max only, tooltip on hover, `<details>` table fallback. Razor reserves the `<text>` tag, so SVG text is emitted through a `MarkupString` helper — see `Shared/SalesTrendChart.razor`.

## Routes

Every page carries an Indonesian route plus its old English one (`/produk` + `/products`, etc.) so existing links keep working. Non-page endpoints: `/api/v1/…`, `/swagger`, `/api/payments/{provider}/callback`, `/pembayaran/{sukses|gagal}`, `/kesalahan`.
